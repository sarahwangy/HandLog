一场"翻译接力"

想象你把一张潦草的字条塞进一条传话筒队伍：第一个人把声音变成文字，第二个人把文字整理成一份漂亮的复盘，第三个人把它归档进笔记本。

每个人只做自己那一件事，谁都不知道全局——但接力完成后，你得到了一份结构化的日记。

第一站：浏览器怎么录音

这段代码来自 src/hooks/useWhisper.ts——它负责问你的手机要麦克风权限、录音、再把录音送出去。

CODE 

const startRecording = async () => {
  const stream = await navigator.mediaDevices.getUserMedia({ audio: true });
  const mimeType = MediaRecorder.isTypeSupported("audio/mp4")
    ? "audio/mp4"
    : "audio/webm";
  const recorder = new MediaRecorder(stream, { mimeType });
  recorder.onstop = async () => {
    const audioBlob = new Blob(chunks, { type: mimeType });
    const formData = new FormData();
    formData.append("audio", audioBlob);
    const response = await fetch("/api/transcribe", {
      method: "POST",
      body: formData,
    });
  };
  recorder.start();
};
PLAIN ENGLISH

开始录音这件事，是一个异步过程——要等手机的麦克风权限批下来才能继续。

向浏览器申请麦克风权限，得到一条"声音数据流"。

检查手机支持哪种音频格式，优先用 mp4，不支持就退而求其次用 webm。

用拿到的格式，创建一个真正的"录音机"对象。

当你点击"停止录音"时，把录到的声音打包成一个音频文件（Blob）。

再把这个音频文件塞进一个"表单包裹"（FormData）里，方便通过网络送出去。

把这个包裹寄给后端的 /api/transcribe 地址，也就是"耳朵"的接待窗口。

用 POST 方式发送——意味着"我要交给你一些数据"，不是单纯"问你要数据"。

最后，按下"开始录音"按钮，一切才真正启动。

第二站：耳朵怎么听懂人话

这段代码来自 src/app/api/transcribe/route.ts——它把音频文件转发给 OpenAI 的 Whisper 模型，请它"翻译"成文字。

CODE 

const audioFile = new File([audioBlob], "recording.webm", { type: audioBlob.type });
const response = await openai.audio.transcriptions.create({
  file: audioFile,
  model: "whisper-1",
  prompt: "这是一段日记录音，请保留所有标点符号。今天天气很好，我去了咖啡馆，见了老朋友。",
});
PLAIN ENGLISH

把浏览器送来的音频数据，重新包装成一个标准"文件"对象，方便交给 Whisper。

调用API，把文件交给 OpenAI，让它转录成文字。

这里就是那个文件本体。

指定用哪个模型来"听"——这里用的是 whisper-1。

给一个"提示词"，像是提前跟耳朵打个招呼："这是日记，别漏掉标点"，帮它转录得更准确。

发出请求，等它把文字结果传回来。

第三站：大脑整理完，交给笔记本

这段代码来自 src/app/api/process/route.ts——是整条接力棒的核心衔接点：大脑整理完，立刻交给笔记本归档。

CODE 

const review = await generateDailyReview(journal, date);
// 拿到 Claude 生成的结构化结果后...
await findOrCreateWeekPage(date);
await appendDailySummary(date, journal);
await appendReviewBlocks(weekPageId, review);
PLAIN ENGLISH

让大脑（Claude）读一遍你今天的日记文字，生成一份结构化的复盘。

从这里开始，我们手里已经是大脑整理好的结果了。

先去笔记本里找这周的页面——没有就新建一页。

把今天的原始日记内容追加进笔记本里存一份底稿。

再把大脑整理出的复盘内容，也写进这周的页面里。

🔗
为什么要拆开这三步

把"整理复盘"和"存进笔记本"拆成两个独立步骤，是因为它们各自可能出错——如果只有存笔记本失败了，你不用重新整理一遍复盘。

检验一下：你能追踪这条链路吗？

这三道题不考你背代码，考你能不能用这条链路去推理新情况。

1. 如果你选择打字而不是录音，上面这条链路会跳过哪一步？

2. 如果转录出来的文字全是错别字，问题最可能出在链路的哪个环节？

3. 为什么要先转文字、再让大脑整理，而不是让大脑直接"听"录音？
