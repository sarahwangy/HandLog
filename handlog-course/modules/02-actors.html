认识主要角色

同一个页面，其实是两个"演员"在轮流上场

你打开 Capture 页面时，加载了两个文件

你打开 Capture 页面时，其实同时加载了两个文件——一个你几乎看不出存在，另一个才是你真正在跟它互动的。

这不是巧合，而是 Next.js 项目里一个非常常见的搭配模式。

🎬
导演（page.tsx）

在服务器端跑，从不直接上场表演，只负责"这个人有没有登录"之类的把关。

🎭
演员（XxxContent.tsx / CaptureForm.tsx）

在浏览器端跑，真正在台上和你互动——录音、打字、点按钮，都归它管。

🧰
道具管理员（lib/ 里的文件）

负责准备所有跟外部世界打交道的工具——比如怎么问 Claude、怎么写进 Notion。

剧组名单：文件地图

不用死记每个文件叫什么，先建立一张"谁负责什么"的地图，之后跟 AI 沟通时才能说得准。

app/ 页面和后端接口都放这里
[locale]/capture/ 录入日记的页面
page.tsx "导演"：服务器端，检查登录、准备数据
CaptureForm.tsx "演员"：浏览器里跑，处理录音/打字/按钮
review/, dashboard/, history/, timeline/, chat/, login/ 每个都是同一套"导演 + 演员"搭配
api/ 后端接口，不渲染任何画面，只负责"干活"
hooks/ 给"演员"用的专用小工具
useWhisper.ts 封装录音逻辑
useAutosave.ts 每隔几秒自动把草稿存起来
lib/ 道具管理员：负责跟外部世界打交道
claude.ts 所有跟 Claude 对话的代码，401 行
notion.ts 所有跟 Notion 读写的代码，1150 行（全项目最大文件）
notion-schema.ts "翻译表"：程序内部字段名 ↔ Notion 里的中文列名
auth.ts 登录规则
kv.ts 一个"便利贴"式的临时存储
prompts/ 喂给 Claude 的"说明书"
daily-review.md / weekly-review.md / monthly-review.md 不同周期的复盘指令

演员的日常：自动保存草稿

这是 useAutosave.ts 里真实的一小段——一个专门负责"你停止打字 3 秒后自动存草稿"的hook。

CODE 

if (timerRef.current) clearTimeout(timerRef.current);

setStatus("idle"); // 重置为 idle，等待下一次保存

timerRef.current = setTimeout(() => {
  save(content);
}, delay);
PLAIN ENGLISH

如果上一个"倒计时"还没响，先取消它——不然会存好几次重复的草稿。

把保存状态标成"还没存"，让界面上能显示出来。

重新开始一个倒计时：等 delay（默认 3000 毫秒，也就是 3 秒）之后，再真正去保存。

这种"每次输入都重新计时，停下来才真正执行"的写法，业内叫防抖（debounce）——你敲键盘越快，它越"忍着不存"，直到你停下来。

关键洞察

把"检查权限"和"处理交互"拆成两个文件，是工程里的重要原则——业内叫"关注点分离"。这也是为什么 HandLog 把 Claude 调用逻辑单独放进 lib/claude.ts，而不是直接写在 CaptureForm.tsx 里。
