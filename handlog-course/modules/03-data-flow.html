数据怎么流动——从一段文字到 Notion 里的一个折叠块

你在 Notion 里点开的那个"复盘"折叠框，其实是程序分两次快递才"造"出来的

先想象一次快递打包

你的日记文字，就像一件要寄出的商品。Claude 把它"打包"成一个标准化的包裹——这个包裹在程序世界里有个名字，叫 JSON。

但快递偶尔会"包装变形"——AI 写出来的 JSON 有时候不完全合规。Notion 这位收货员，还得会一手"拆歪包装"的绝活，才能把东西正确放进你笔记本的格子里。

💡
这周你会学到的核心问题

AI 吐出来的是一段文字，但程序要用的是结构化数据。从文字到结构化数据、再到 Notion 复杂的块结构，中间经过好几层"翻译"和"容错"——这是几乎所有 AI 应用都要处理的通用问题。

质检员的第一招：只剪最外层完整的包裹

Claude 有时候会在 JSON 前后多说几句客套话，比如"好的，这是你的复盘："。extractJson 不会傻乎乎地找最后一个 大括号， 而是用"括号计数法"精确数出真正闭合的那一个。

CODE 

// 从 Claude 的响应里提取 JSON 对象，忽略前后多余的文字或 markdown 代码块
function extractJson(text: string): string {
  const start = text.indexOf("{");
  if (start === -1) throw new Error("No JSON object found in response");

  // 用括号计数法找到真正匹配的根级闭合括号，而不是 lastIndexOf
  let depth = 0;
  let inString = false;
  let escape = false;
  for (let i = start; i < text.length; i++) {
    const ch = text[i];
    if (escape) { escape = false; continue; }
    if (ch === "\\" && inString) { escape = true; continue; }
    if (ch === '"') { inString = !inString; continue; }
    if (inString) continue;
    if (ch === "{") depth++;
    else if (ch === "}") {
      depth--;
      if (depth === 0) return text.slice(start, i + 1);
    }
  }
  throw new Error("JSON object not properly closed (truncated response)");
}
PLAIN ENGLISH

先找到第一个 { ——包裹的开箱位置。没找到就直接报错，说明这次没打包出任何东西。

准备一个计数器 depth，从 0 开始；另外记录"现在是不是在一段引号字符串里面"。

逐个字符扫描：如果在字符串里，先原样跳过（字符串里的花括号不算数，比如日记正文里写的表情符号或符号）。

碰到 { 就把计数器加一，碰到 } 就减一——每一层花括号都被记一笔账。

当计数器第一次回到 0，说明最外层的包裹刚好在这里闭合——把这一段截出来就是完整、干净的 JSON，不用管后面 Claude 还说了什么客套话。

翻译标签表：程序内部名字 ≠ 你在 Notion 里看到的列名

拿到干净的 JSON 后，程序里的字段叫 score，但你在 Notion 表格里实际看到的列名是"打分"——这张 字段映射表 就是负责这层翻译的。

CODE 

export const DEFAULT_FIELD_MAPPING: JournalFieldMapping = {
  name: "Name",
  dailySummary: "简短日常",
  labels: "label标签",
  score: "打分",
  insight: "一句话感悟",
  review: "复盘",
  nextSteps: "下一步",
  handlogImage: "手绘复盘图",
  psychNote: "心理学正能量话",
};
PLAIN ENGLISH

左边是程序写代码时用的英文名字，右边引号里是你在 Notion 表格里实际看到的中文列名。

比如程序算完 score（打分）之后，要往 Notion 写数据，就查这张表：score 对应的列名叫"打分"。

这样做的好处是：以后你想把 Notion 里"打分"这一列改名叫"评分"，只需要改这一行，不用满代码库去找 score 这个词改。

最后一关：造一个可以点开的"复盘"折叠框

你在 Notion 看到的那个可以点开的 折叠块（Toggle）， 外面是个能点开的壳，里面套了一个带图标的 高亮块（Callout） ——这两层是分两次 API 调用才造出来的，不是一次搞定。

1
先造一个空盒子

调用一次 API，在页面里建一个 Toggle，Toggle 里放一个内容还是空的 Callout——这时候程序还不知道这个 Callout 真正的编号（ID）是什么。

2
回头查一下盒子的编号

再调用一次 API，去问 Notion："刚才那个 Toggle 里面，你给它装的 Callout 编号是多少？"——拿到真正的 ID，才能往里塞东西。

3
把复盘内容塞进去

评分、感悟、下一步这些内容块，最后都追加到这个真正拿到手的 Callout 编号下面，你才会在 Notion 里看到点开折叠框有完整内容。

CODE · Step 1 

// Step 1：建 Toggle，Toggle 里包一个空 Callout（作为内容容器）
// eslint-disable-next-line @typescript-eslint/no-explicit-any
const toggleRes = await withAuthCheck(() =>
  notion.blocks.children.append({
    block_id: pageId,
    children: [
      {
        type: "toggle",
        toggle: {
          rich_text: [{ type: "text", text: { content: `周${dayChar}复盘` }, annotations: { bold: true } }],
          color: "default",
          children: [
            {
              type: "callout",
              callout: {
                rich_text: [],          // 空标题，内容在子块里
                icon: { type: "emoji", emoji: "📋" },
                color: "blue_background",
              },
            } as Parameters<typeof notion.blocks.children.append>[0]["children"][0],
          ],
        },
      } as Parameters<typeof notion.blocks.children.append>[0]["children"][0],
    ],
  })
) as { results: { id: string; type: string }[] };
PLAIN ENGLISH

调用 Notion 的 API，往这个页面里追加一块内容。

要加的内容是一个 Toggle（折叠块），标题写"周X复盘"，加粗显示。

这个 Toggle 里面预先塞了一个空的 Callout（高亮块），带个 📋 图标——先当个占位的空盒子。

这个空 Callout 现在还没有内容，也不知道自己的真实编号——那是下一步才要去问的。

CODE · Step 2 

// Step 2：找到刚建的 Toggle 里的 Callout ID
const toggleId = toggleRes.results[0]?.id;
if (!toggleId) return;

const toggleChildren = await withAuthCheck(() =>
  notion.blocks.children.list({ block_id: toggleId })
) as { results: { id: string; type: string }[] };

const calloutId = toggleChildren.results.find(b => b.type === "callout")?.id;
if (!calloutId) return;
PLAIN ENGLISH

从第一次 API 调用的返回结果里，拿到刚创建的 Toggle 自己的编号。如果没拿到就直接放弃（说明创建失败）。

再发一次 API 请求，问 Notion："这个 Toggle 底下都有哪些子内容？"——这才是第二次真正的网络请求。

在返回的子内容列表里，找到类型是 "callout" 的那一个，取出它的真实编号。

有了这个真实编号，后面才能放心地往这个 Callout 里追加评分、感悟、下一步这些内容。

检验一下：你能顺着这条快递线找到问题吗？

如果 Claude 返回的文本前面多了一句"好的，这是你的复盘："，extractJson 还能正确工作吗？

场景

你想在 Notion 数据库里新增一列"今日运动"，除了在 Notion 网页里手动加一列，代码这边最少还要改哪里？
